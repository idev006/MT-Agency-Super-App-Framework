# ADR-002 — Repository SSOT boundaries and generated publishing

- **Date:** 2026-11-17
- **Status:** Accepted for repository organization only; not a production deployment approval
- **Scope:** Cross-application repository organization
- **Owner/approver:** Project owner instruction to implement existing approved structure

## Decision
1. `blueprint/` stores mandatory, application-agnostic development standards and architecture decisions. The platform identity/SSO documents stay in `blueprint/platform/` and do not override the universal Web App Blueprint.
2. `apps/<app-id>/docs/` stores project-specific specifications, policy/PDPA drafts, operational SOPs, test evidence and project decisions.
3. `apps/<app-id>/poc/` stores prototypes; production `src/` and `tests/` are created as implementation matures. Prototypes are not misrepresented as production applications.
4. `portal/` contains only the authoritative application directory definition and templates.
5. `_site/` is generated by CI from canonical files, is ignored by Git, and must never be committed. No second QR scanner source in `docs/`.
6. Existing redirect/pointer Markdown files remain temporarily for compatibility and are not canonical document content. Remove only after inbound-link audit.

## Non-decisions
This ADR does **not** approve policy changes, production rollout, security certification, or a migration of the existing standalone QR scanner to Vue. Any changes to required vehicle photos, parking/visitor activation, access rules, or personal-data retention require a separately recorded decision from the responsible authority.

## Verification
Run `node scripts/validate-ssot.mjs`, `node scripts/build-pages.mjs _site`, and `node scripts/validate-ssot.mjs --built _site`. CI verifies sources and generated outputs separately. Record mobile device evidence under Vehicle Contact docs.
